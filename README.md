# Deutsch bewusst · Telegram-бот — Этап 1

Каркас, каталог продуктов, модуль оплаты, выдача минибука.

## Структура

```
netlify/functions/telegram.mjs   вебхук — точка входа
src/config.js                    имена таблиц и переменные окружения
src/db.js                        весь доступ к Supabase
src/ui.js                        тексты, клавиатуры, форматирование
src/menu.js                      /start, разделы, карточки, кабинет
src/payment.js                   оплата, приём квитанций, админ-подтверждение
src/bot.js                       сборка бота
scripts/set-webhook.mjs          установка вебхука
```

## Переменные окружения (Netlify → Site settings → Environment variables)

| Имя | Что это |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `SUPABASE_URL` | URL проекта Supabase |
| `SUPABASE_SERVICE_KEY` | **service_role** ключ, не anon |
| `ADMIN_CHAT_ID` | `-1004339011404` |
| `OWNER_TG_ID` | твой личный tg_id — узнать командой `/whoami` |
| `WEBHOOK_SECRET` | любая случайная строка, например `db_9f3k2xQ` |

## Запуск

1. Залить код в репозиторий, подключить его к Netlify.
2. Прописать переменные окружения, дождаться деплоя.
3. Установить вебхук с локальной машины:

```bash
BOT_TOKEN=... SITE_URL=https://твой-сайт.netlify.app WEBHOOK_SECRET=... node scripts/set-webhook.mjs
```

В ответе должно быть `"ok":true` и `"url"` с адресом сайта.

4. Написать боту `/whoami`, скопировать свой id в `OWNER_TG_ID`, передеплоить.

## Как включить минибук

1. Отправь PDF минибука **в админ-группу** — бот ответит его `file_id`.
2. В Supabase → SQL Editor:

```sql
update products
   set payload     = jsonb_build_object('file_id', 'ВСТАВИТЬ_FILE_ID'),
       price_eur   = 12.00,
       title       = '📘 Минибук с упражнениями',
       description = 'Текст карточки',
       is_active   = true
 where slug = 'minibook';
```

3. Написать боту `/start` и проверить весь путь до выдачи файла.

# Этап 2 — группы, лист ожидания, помесячная оплата

## Что добавилось

```
src/groups.js                        группы, лист ожидания, счета, напоминания
netlify/functions/cron-reminders.mjs ежедневные напоминания о продлении
```

Изменены: `src/menu.js`, `src/payment.js`, `src/bot.js`.

## Порядок обновления

1. Запустить миграцию `002_stage2_groups.sql` в Supabase → SQL Editor.
2. Залить обновлённые файлы в GitHub (файлы с теми же именами заменяются).
3. Netlify пересоберётся сам.

## Как это работает

**Запись без оплаты.** Человек бронирует место и выбирает удобное время.
Место занято, счётчик растёт, деньги пока не берутся.

**Счёт выставляешь ты.** Команда `/groups` в чате с ботом → выбрать группу →
видно список участников и кто какое время выбрал → кнопка
«Выставить счёт всем неоплатившим». Бот рассылает сумму и реквизиты.

**Оплата** идёт через тот же модуль, что и минибук: квитанция → имя
отправителя → твоё подтверждение. После подтверждения участник получает
статус `active`, поле `paid_until` = +1 месяц, и ссылку на чат группы.

**Продление.** Раз в сутки бот проверяет, у кого заканчивается оплата,
и присылает напоминание с кнопкой «Продлить». Через `grace_days` дней
после окончания участник возвращается в статус `reserved`, а тебе
приходит уведомление.

## Что заполнить руками

```sql
-- расписание, когда согласуешь с группой
update groups set schedule_text = 'вт/чт 18:00' where level = 'A0';

-- ссылка на закрытый чат группы (бот должен быть админом чата)
update groups set chat_invite_link = 'https://t.me/+xxxxx' where level = 'A0';

-- твой tg_id, чтобы приходили уведомления о записях
update teachers set tg_id = ВАШ_ID where role = 'owner';
```

## Настройки этапа 2 (таблица settings)

| Ключ | Значение по умолчанию | Что делает |
|---|---|---|
| `waitlist_levels` | `A2,B1` | уровни для листа ожидания |
| `renew_remind_days` | `3` | за сколько дней напоминать о продлении |
| `grace_days` | `3` | сколько дней терпим просрочку |

- [ ] Повторная запись выдаёт «Ты уже записана»

# Практика дня

## Что добавилось

```
src/practice.js                       банк заданий, серия, разбор ответов
netlify/functions/cron-practice.mjs   ежечасная проверка, кому пора слать
```

Изменены: `src/ui.js` (кнопка в меню), `src/bot.js`.
Миграция: `004_practice.sql` — таблицы и 25 стартовых заданий уровня А0.

## Как работает

Человек включает «Задание дня» и сразу получает первое. Дальше бот
присылает по одному заданию в выбранный час. Ответ — кнопкой, после
чего бот показывает правильный вариант и объясняет правило.

Серия считается по календарным дням Киева: ответил на следующий день —
серия растёт, пропустил — начинается заново. Повторные ответы на то же
задание в статистику не идут.

После пятого решённого задания бот один раз мягко предлагает минибук.

## Как добавлять задания

```sql
insert into practice_tasks (level, topic, question, options, correct_ix, explanation, sort_order)
values (
  'A0',
  'тема',
  'Текст вопроса с ___ пропуском',
  '["вариант 1","вариант 2","вариант 3"]'::jsonb,
  1,                       -- индекс правильного: 0 = первый
  'Объяснение правила. Поддерживается <b>жирный</b>.',
  260
);
```

Важно: `correct_ix` считается с нуля. Варианты — 2–4 штуки, каждый
должен быть коротким, иначе не поместится на кнопке.

Посмотреть, что уже есть:

```sql
select sort_order, topic, question from practice_tasks order by sort_order;
```

## Настройки

| Ключ | Что делает |
|---|---|
| `practice_default_hour` | час по умолчанию для новых подписчиков |
| `practice_enabled` | `false` полностью останавливает рассылку |

## Проверка

- [ ] В главном меню появилась кнопка «🎯 Задание дня»
- [ ] «Включить» → сразу приходит первое задание
- [ ] Правильный ответ → зелёная отметка и разбор
- [ ] Неправильный → показывает верный вариант и объясняет
- [ ] «Ещё задание» выдаёт следующее, а не то же самое
- [ ] Смена времени сохраняется

# Рассылка, ответ на сообщения, «поделиться»

## Что добавилось

```
src/extras.js   рассылка по сегментам + ответ на любое сообщение
```

Изменены: `src/bot.js` (регистрация последним), `src/practice.js` (кнопка «поделиться»).
Миграции не требуются.

## Рассылка

Команда `/send` в личке с ботом — доступна только владельцу (`OWNER_TG_ID`).

1. Выбрать сегмент — рядом сразу видно, сколько человек в нём
2. Прислать текст сообщения
3. Бот покажет предпросмотр ровно в том виде, в каком его получат люди
4. «Отправить» — и в конце отчёт: доставлено, заблокировали, не дошло

Сегменты: все · решают задания · лист ожидания · участники групп ·
купили минибук.

Разметка сохраняется: жирный, курсив, ссылки. Отменить на любом
шаге — `/cancel`.

Кто заблокировал бота, помечается автоматически и в следующие рассылки
не попадает.

**Ограничение:** отправка идёт по 40 мс на сообщение, чтобы не упереться
в лимиты Telegram. До сотни получателей проходит спокойно; если база
вырастет за несколько сотен, рассылку нужно будет переносить в фоновую
задачу.

## Ответ на любое сообщение

Раньше бот молчал, если ему просто писали текст. Теперь любое сообщение,
которое не разобрал ни один сценарий, получает короткий ответ с меню,
а тебе в админ-чат приходит карточка с текстом и автором.

Работает и с фото, голосовыми и файлами — в админ-чат придёт пометка,
что это не текст.

## Кнопка «поделиться»

Появляется в разделе «Задание дня» и после выполненной дневной нормы.
Открывает стандартный диалог Telegram: человек выбирает, кому переслать.
Ссылка уходит с меткой `share`, поэтому в статистике видно, сколько
людей пришло именно так:

```sql
select coalesce(source, 'без метки') as откуда, count(*)
  from users group by 1 order by 2 desc;
```

# Статистика, индивидуальные уроки, возврат пропавших

Миграция: `007_lessons.sql`.
Новый файл: `src/lessons.js`. Изменены: `bot.js`, `payment.js`, `groups.js`,
`practice.js`, `extras.js`, `netlify/functions/cron-reminders.mjs`.

## /stats

Команда в личке с ботом, только для владельца. Показывает людей,
подписки на практику, ответы за сегодня, участников групп, лист ожидания,
свободные и оплаченные слоты, сумму оплат и сколько заявок ждут
подтверждения.

## Индивидуальные уроки

**Ты добавляешь время** одной командой:

```
/addslots 25.07 15 16 18
```

Дата, потом часы через пробел. Время по Киеву, урок 60 минут.
Одна команда на день.

```
/slots            посмотреть ближайшие слоты и их статус
/delslots 25.07   удалить свободные слоты за день
```

**Ученик** заходит в «Занятия с преподавателем» → «Индивидуальные уроки»,
выбирает день и время. Слот замораживается на час, дальше обычная оплата
через квитанцию. После подтверждения бот ставит статус «оплачено» и
напоминает за сутки и за час.

Если за час не оплатили — слот сам возвращается в общий список.

**Цена** берётся из настроек:

```sql
update settings set value = '20' where key = 'lesson_price_eur';
```

**Время везде по Киеву** и подписано явно. Отдельные часовые пояса
учеников намеренно не заводим — на текущем масштабе это лишняя сложность.

## Возврат пропавших

Раз в сутки бот находит тех, кто подписан на практику, но молчит
`winback_days` дней (по умолчанию 3), и присылает одно сообщение с
готовым заданием. Повторно — не чаще раза в неделю.

```sql
update settings set value = '4' where key = 'winback_days';
```

## Расписание фоновых задач

`cron-reminders` теперь работает **каждый час**: снимает просроченные
брони и шлёт напоминания об уроках. Продления и возврат пропавших
запускаются раз в сутки, в 10 утра по Киеву.

`cron-practice` по-прежнему ежечасно рассылает задание дня тем, у кого
настал их час.

## Проверка

- [ ] `/stats` показывает сводку
- [ ] `/addslots` на завтра создаёт слоты, `/slots` их показывает
- [ ] Ученик видит день и время, бронирует, получает счёт
- [ ] Через час неоплаченная бронь освобождается
- [ ] После подтверждения приходит подтверждение с датой

# Автопостинг в канал

Миграция: `008_channel.sql`. Новый файл: `src/channel.js`.
Изменены: `menu.js`, `netlify/functions/cron-practice.mjs`.

## Что делает

Раз в сутки бот публикует в канал одно задание в виде **нативной
викторины** Telegram. Люди отвечают прямо в канале, Telegram сам
показывает правильный вариант и пояснение.

Каждый четвёртый пост сопровождается ссылкой на бота — «хочешь такие
задания каждый день, они здесь».

Задания берутся по порядку, от простых к сложным, и каждое публикуется
только один раз.

## Настройка

Бот должен быть **администратором канала** с правом публиковать.

```sql
update settings set value = '@imya_kanala' where key = 'channel_id';
update settings set value = 'https://t.me/imya_kanala' where key = 'channel_url';
update settings set value = '11'   where key = 'channel_post_hour';
update settings set value = 'true' where key = 'channel_enabled';
```

Для публичного канала подойдёт `@username`. Для приватного нужен
числовой id вида `-100...`.

Выключить в любой момент:

```sql
update settings set value = 'false' where key = 'channel_enabled';
```

## Приглашение подписаться

Если заполнен `channel_url`, при первом `/start` бот проверяет подписку
и, если человек не подписан, один раз предлагает. Ничего не блокирует —
доступ ко всем функциям остаётся открытым.

## Ограничения Telegram

- Пояснение к викторине — не больше 200 символов, длинные разборы
  обрезаются по границе предложения
- Вариант ответа — не больше 100 символов
- Викторина всегда анонимная, кто как ответил, не видно

# Абонементы и две длительности

Миграция: `009_packages.sql`. Изменены: `lessons.js`, `payment.js`.

## Цены (таблица settings)

| Ключ | Что это |
|---|---|
| `price_single_45` / `price_single_60` | разовое занятие, EUR |
| `price_pack_45` / `price_pack_60` | абонемент, EUR |
| `pack_size` | занятий в абонементе (10) |
| `pack_valid_days` | срок действия абонемента (120) |

Меняются одной строкой, деплой не нужен:

```sql
update settings set value = '120' where key = 'price_pack_45';
```

## Слоты двух длительностей

```
/addslots   25.07 15 16 18    уроки по 60 минут
/addslots45 25.07 15 16 18    уроки по 45 минут
```

В `/slots` рядом с каждым слотом видно его длительность.

## Как работает абонемент

Ученик покупает абонемент на 10 занятий выбранной длительности. Дальше
он просто выбирает время — занятие **списывается автоматически**, оплата
не запрашивается. Бот показывает, сколько осталось и до какого числа.

Абонемент привязан к длительности: купленный на 45 минут не спишется за
урок на 60. Так и задумано — иначе математика цен не сходится.

Срок действия считается от даты покупки. Просроченные занятия не
списываются, но и не удаляются — при желании можно продлить руками:

```sql
update lesson_credits set expires_on = '2026-12-31'
 where user_id = (select id from users where tg_id = 123456789);
```

## Экономия показывается сама

На экране абонемента бот считает разницу с ценой десяти разовых и
пишет её явно. Пересчитывать при смене цен не нужно.

# Часовой пояс, минуты, правила отмены

Миграция: `010_lessons_tz.sql`. Переписан `src/lessons.js`.

## Часовой пояс расписания

```sql
update settings set value = 'Europe/Berlin' where key = 'lesson_tz';
```

В этом поясе ты **вводишь** слоты и в нём же их **видят ученики**.
Подпись «по Берлину» подставляется автоматически. Переход на летнее
время учитывается — слот, заведённый в июле, не съедет в октябре.

Сменить на Киев можно одной строкой, уже созданные слоты просто
отобразятся в новом поясе.

## Добавление слотов

```
/addslots   27.07 16:10 17:30 19     уроки по 60 минут
/addslots45 27.07 16:10 18           уроки по 45 минут
```

Время можно писать с минутами (`16:10`) и без (`19`). Бот в ответ
покажет, что именно создал, — удобно проверить, что не ошиблась поясом.

Если дата уже прошла в этом году, бот поймёт её как следующий год.

## Правила отмены

Хранятся в настройке `cancel_policy` и показываются в четырёх местах:
на экране уроков, в карточке абонемента, после оплаты урока и после
записи по абонементу.

```sql
update settings set value = 'новый текст' where key = 'cancel_policy';
```

## Когда слотов нет

Раздел всё равно показывает цены, формат и правила отмены, а вместо
расписания появляется кнопка «Оставить заявку на время». Человек пишет,
когда ему удобно, заявка падает тебе в админ-чат.
